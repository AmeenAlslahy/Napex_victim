# NAP-EX — المعمارية التقنية الشاملة

> وثيقة معمارية رسمية — منصة مكافحة الابتزاز الإلكتروني (مشروع تخرج)

## 1. نظرة عامة

NAP-EX منظومة وطنية من ثلاثة مكونات متكاملة تُدير رحلة الضحية كاملة:
من **لحظة الاكتشاف** → **توثيق الدليل** → **الإجراء القانوني** → **الدعم والاستعادة**.

```
┌─────────────────┐      HTTPS/WS       ┌─────────────────┐
│  تطبيق الضحية   │ ──────────────────► │  الخادم المركزي │
│  Flutter+Kotlin │ ◄────────────────── │  FastAPI        │
└─────────────────┘   JWT + توقيع طلبات  └────────┬────────┘
                                                  │
                                       ┌──────────▼─────────┐
                                       │ لوحة التحكم الحكومية│
                                       │ React + TypeScript │
                                       └────────────────────┘
```

## 2. مكونات المنظومة

| المكوّن | التقنية | المسؤولية | القياس |
|---|---|---|---|
| **تطبيق الضحية** | Flutter 3.47 + Kotlin (Android) | كشف الابتزاز، حفظ الأدلة المشفرة، الإبلاغ، الدعم النفسي | 37 اختباراً · analyze نظيف · APK مبني |
| **الخادم المركزي** | FastAPI + SQLAlchemy + JWT | استقبال البلاغات، التحقيق الجنائي، السير القانوني، الحذف السحابي، تحليل الأنماط | 28 اختباراً · مختبر حياً |
| **لوحة التحكم** | React 18 + TypeScript + Vite | القيادة والإدارة للمحققين والمشرفين | 11 صفحة · TS نظيف · بناء ناجح |

## 3. معمارية تطبيق الضحية — Clean Architecture

```
┌──────────────────────────────────────────────┐
│ Presentation  (Screens, Riverpod, go_router) │
├──────────────────────────────────────────────┤
│ Domain        (Entities, UseCases, Interfaces)│ ← نقي 100%
├──────────────────────────────────────────────┤
│ Data          (Models, DAOs, APIs, Mappers)  │
├──────────────────────────────────────────────┤
│ Platform      (Kotlin Services, Channels)    │
└──────────────────────────────────────────────┘
```

**قواعد صارمة:**
- Presentation تعتمد على Domain فقط.
- Domain لا يعتمد على أي شيء (Entities + UseCases + واجهات المستودعات).
- Data تنفّذ واجهات Domain وتعتمد عليها.
- Platform يُستدعى من Data عبر واجهات (قابل للاستبدال والاختبار).

**نمطا معالجة الأخطاء (قرار معماري موثق):**
- المستودعات تُعيد Records: `(T?, Failure?)` — استدعاء مباشر خفيف.
- الـ UseCases تُوحّد الدلالة بـ `Either<Failure, T>` (dartz) لواجهة Presentation.

## 4. رحلة الرسالة (Data Flow الأساسي)

```
1. رسالة تصل (SMS / إشعار واتساب / تيليجرام…)
2. خدمة Kotlin تلتقطها (AccessibilityService / NotificationListener / SmsReceiver)
3. MessageEventBus → EventChannel → MessageCollectorChannel (Dart)
4. CollectorController: حد أمان 30 رسالة/دقيقة + منع تكرار (معرف حتمي)
5. فحص قائمتَي الحظر (الوطنية + الشخصية) → تحليل مفروض إن تطابق
6. KeywordClassifier: تطبيع عربي → أوزان → ثقة 1−e^(−S/k)
7. عتبة الحساسية من إعدادات المستخدم (0.70–0.95)
8. ابتزاز مؤكد → CreateReportUseCase → حفظ محلي مشفر → محاولة إرسال
9. إشعار محلي (حسب النمط وساعات الحماية) + حوار تنبيه
10. الخادم: رقم رسمي EXT-YYYY-XXXXXX → سلسلة حفظ → بث WebSocket للوحة
11. الجهة المختصة: تحقيق جنائي → أوامر قانونية → حذف سحابي → إشعار الضحية تلقائياً
```

## 5. معمارية الأمان

| الطبقة | الآلية |
|---|---|
| **التشفير الساكن** | AES-256-CBC + HMAC-SHA256 (Encrypt-then-MAC) — التحقق **قبل** فك التشفير بمقارنة زمن ثابت |
| **المفاتيح** | مفتاح رئيسي عشوائي في Keystore (flutter_secure_storage)، اشتقاق مفتاحين منفصلين (domain separation) مع كاش في الذاكرة |
| **سلامة الأدلة** | SHA-256 لكل دليل + تحقق إعادة حسابي + سلسلة حفظ (custody_entries) لكل إجراء |
| **النقل** | HTTPS + Bearer JWT (access 30د / refresh 7أيام) + ترويسات توقيع `X-Signature/X-Nonce/X-Request-Id` |
| **التحكم بالوصول** | RBAC بأربعة أدوار (victim/investigator/supervisor/admin) + فصل صارم بين واجهات الضحية والتشغيل |
| **الخصوصية** | تجزئة أرقام المرسلين، جهاز الطوارئ المحلي لا يرفع شيئاً، سياسة احتفاظ (رسائل 30 يوماً)، حق التصدير |
| **المقاومة** | حد فيض 30 رسالة/دقيقة، منع تكرار بمعرفات حتمية، retry بتراجع أُسّي + jitter |

## 6. الخادم — 15 مجموعة واجهات

```
auth (تسجيل/OTP/JWT)  ·  reports  ·  evidence  ·  analysis (+patterns)
stats  ·  forensic (ضبط→تصوير→استخراج→حذف آمن)  ·  legal (أوامر+مستندات)
cloud (takedown)  ·  victim (إشعارات)  ·  blocklist (وطنية)
me (حظر شخصي + تصدير)  ·  admin (users/audit)  ·  ws (بث فوري)
```

**التكاملات التلقائية المختبرة:**
- إكمال الحذف الآمن → إشعار `files_deleted` للضحية.
- تنفيذ أمر قانوني سحابي → طلب `CloudOrder` تلقائي.
- إتمام الإزالة السحابية → إشعار `cloud_cleaned` للضحية.

## 7. تحليل الأنماط — كشف المبتز المحترف

تجميع البلاغات حسب `sender_hash` وحساب: عدد الضحايا، البلاغات، التطبيقات، مدة النشاط.
**تصنيف «محترف»:** ضحيتان+ أو 4 بلاغات+.
**درجة الخطورة:** `ضحايا×3 + بلاغات + تطبيقات (+5 إذا امتدت ≥30 يوماً)`.

## 8. قرارات معمارية رئيسية (ADRs مختصرة)

| # | القرار | البديل | السبب |
|---|---|---|---|
| 1 | CBC+HMAC (Encrypt-then-MAC) | AES-GCM | حزمة encrypt لا توفر GCM بشكل موثوق؛ التحقق قبل الفك يعادل أمنياً |
| 2 | sqflite + DAOs يدوية | Drift + codegen | ترجمة فورية بلا build_runner، تحكم كامل بالاستعلامات |
| 3 | Riverpod يدوي | injectable/get_it | مركزية الـ DI في ملف واحد قابل للقراءة |
| 4 | محرك قواعد عربي أولاً | انتظار ML | يعمل بلا بيانات، **قابل للتفسير قضائياً**، الواجهة تسمح باستبدال TFLite بسطر |
| 5 | offline-first في الإبلاغ | إرسال مباشر فقط | البلاغ أثمن من الشبكة — يُحفظ مشفراً ويزامن لاحقاً |
| 6 | معرفات رسائل حتمية | UUID عشوائي | منع التكرار عند تسليم البث المزدوج |

## 9. التوسع المستقبلي (خارطة طريق)

1. نموذج TFLite هجين (0.7 TFLite + 0.3 قواعد) — كود التدريب جاهز في `ml/`.
2. موقع جغرافي وتسجيل صوتي اختياري في وضع الطوارئ (صلاحيات + خصوصية).
3. Postgres + Redis + rate limiting خلف nginx للإنتاج.
4. تكامل APIs حقيقي مع مزودي الإزالة (Google/Apple/Meta legal portals).
5. تطبيق iOS (الخدمات الأصلية الحالية أندرويد فقط).

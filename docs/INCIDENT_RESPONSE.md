# NAP-EX — خطة الاستجابة للحوادث (Incident Response)

> إجراءات إلزامية عند أي حادث أمني أو تشغيلي — تُطبق فوراً ولا تُتجاوز.

## 1. تصنيف الحوادث

| المستوى | التعريف | أمثلة | زمن الاستجابة |
|---|---|---|---|
| **P1 — حرج** | تسرب بيانات ضحايا / اختراق الخادم / تلاعب بأدلة | تسريب قاعدة البيانات، تعديل custody | فوري (≤ 1 ساعة) |
| **P2 — عالي** | تعطل خدمة أساسية | الخادم لا يستقبل بلاغات، فشل التشفير | ≤ 4 ساعات |
| **P3 — متوسط** | خلل وظيفي جزئي | فشل مزامنة، بطء شديد | ≤ 24 ساعة |
| **P4 — منخفض** | مشكلة تجميلية/سجل | خطأ واجهة، سجل ناقص | ≤ 72 ساعة |

## 2. فريق الاستجابة (CSIRT)

| الدور | المسؤولية |
|---|---|
| قائد الحادث (المدير/admin) | إعلان الحادث، القرارات، التواصل الرسمي |
| مهندس التشغيل | الاحتواء التقني (Killswitch، عزل، استعادة) |
| مسؤول الأدلة | حفظ السجلات + forensic على الخادم نفسه |
| مسؤول التواصل | إشعار الضحايا/النيابة/الجهة |

## 3. إجراءات الاحتواء الفوري (P1/P2)

1. **الإيقاف الطارئ (Killswitch):**
   ```http
   POST /api/v1/admin/system/killswitch
   { "enabled": true, "reason": "..." }
   ```
   يرفض كل الطلبات عدا `/health` و`/metrics` وواجهات الإدارة — خلال ≤ 3 ثوانٍ.
2. **حفظ الأدلة الرقمية للخادم نفسه:** نسخ logs + DB snapshot قبل أي إصلاح.
3. **عزل:** تدوير `SECRET_KEY` إذا شمل الاختراق المفاتيح، إبطال توكنات (تدوير = سحب تلقائي).
4. **الإصلاح:** ترقيع الثغرة ثم رفع الحجب بعد تحقق الأمان.

## 4. الإخطارات

| الجهة | التوقيت | المحتوى |
|---|---|---|
| الضحايا المتأثرون | ≤ 72 ساعة | نطاق البيانات، الخطورة، الخطوات المقترحة — عبر إشعارات الضحية |
| النيابة/الجهة | ≤ 72 ساعة | تقرير حادث رسمي + أدلة التقنية |
| فريق التطوير | فوري | post-mortem داخلي |

## 5. تحليل ما بعد الحادث (Post-mortem) — خلال 7 أيام

- الخط الزمني الكامل (من أول مؤشر إلى الاستعادة).
- السبب الجذري (Root Cause) — بلا إلقاء لوم أشخاص.
- تقييم أثر البيانات (هل وُصل لمحتوى مشفر؟ ما قيمة الهاشات؟).
- إجراءات منع التكرار + تحديث هذه الوثيقة.
- **توثيق كل ذلك في سجل الحوادث (audit) — الحادث نفسه دليل يُحفظ.**

## 6. النسخ الاحتياطي والاستعادة (Backup & DR)

| البند | القيمة |
|---|---|
| نسخة كاملة يومياً (DB + ملفات الأدلة) | 02:00 فجراً |
| تزايدية كل ساعة | DB WAL/binlog |
| الاحتفاظ | 30 يوماً + نسخة شهرية سنة كاملة |
| الموقع | off-site (سحابة منفصلة / S3 Glacier) |
| **RTO** (أقصى زمن استعادة) | **4 ساعات** |
| **RPO** (أقصى فقد بيانات مقبول) | **ساعة واحدة** |
| اختبار الاستعادة | **شهرياً إلزامي** — نسخة لا تُختبر ليست نسخة |

أداة النسخ: `pg_dump` + أرشفة مجلد uploads مشفراً — تعليمة الاستعادة موثقة في `docs/DEPLOYMENT.md`.

## 7. قائمة تحقق سريعة (P1 Checklist)

```
[ ] تفعيل Killswitch (≤ 3 ثوانٍ)
[ ] إبلاغ قائد الحادث
[ ] Snapshot للنظام المتأثر (لا تلمسه)
[ ] تقييم نطاق البيانات (أي جداول؟ مشفرة؟)
[ ] تدوير المفاتيح إن لزم
[ ] إخطار الضحايا ≤ 72 ساعة
[ ] إخطار النيابة ≤ 72 ساعة
[ ] Post-mortem ≤ 7 أيام
[ ] تحديث الإجراءات الوقائية
```

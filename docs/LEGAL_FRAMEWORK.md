# NAP-EX — الإطار القانوني والتشغيلي

> وثيقة تُحدد الإطار القانوني والمعايير التشغيلية للمنصة — تُعرض في المناقشة وتُكيَّف مع التشريعات المحلية النافذة قبل أي نشر فعلي.

## 1. المبدأ الحاكم

> **المنصة لا "تخترق" ولا "تنسحب" — بل تُدير إجراءات رسمية موثقة.**

كل عمليات الاسترداد والحذف تتم حصراً عبر:
1. أمر قضائي/نيابة عامة موثق في النظام.
2. تنفيذ ميداني بيد جهات مختصة (وليس برمجياً عن بُعد).
3. توثيق كامل في سلسلة الحفظ الرقمية.

## 2. المصطلحات المعتمدة (والبدائل المرفوضة)

| ❌ مصطلح مرفوض | ✅ المصطلح المعتمد | لماذا |
|---|---|---|
| «اختراق جهاز المبتز» | **Forensic Extraction** — استخراج جنائي بموجب أمر | الاختراق جريمة حتى بنيّة حسنة |
| «فرمتة عن بُعد» | **Secure Erase** موثق التنفيذ (DOD 5220.22-M / NIST 800-88) | التنفيذ ميداني بأمر، والتوثيق إلزامي |
| «نحذف من جهاز المبتز» | «نُنسّق تنفيذ الحذف عبر الإجراءات الرسمية» | الفصل بين التتبع والتنفيذ |
| «تجسس» | **Monitoring بإذن صريح** | الأذونات تُطلب من المستخدم وتظهر في الواجهة |

## 3. سلسلة الحفظ الرقمية (Digital Chain of Custody)

**التعريف:** سجل زمني غير قابل للكسر يوثق كل من لمس الدليل وما فعله به.

**التنفيذ في NAP-EX:**
| المرحلة | ما يوثَّق | بواسطة |
|---|---|---|
| الاكتشاف | الرسالة + تحليلها + هاش SHA-256 + تشفير الجهاز | التطبيق تلقائياً |
| الاستلام | `received_from_device` + هاش المرسل | الخادم تلقائياً |
| الأدلة | `evidence_received` + نتيجة مطابقة الهاش | الخادم تلقائياً |
| الضبط/التصوير/الحذف | الجهاز، المكان، الضباط، الأداة، هاش النسخة، طريقة الحذف + هاش التحقق | المحقق (إلزامي حقلياً) |
| الأوامر | الإصدار والتنفيذ + المستند الرسمي المولّد | النظام + المحقق |
| كل تغيير حالة | المُجري + الملاحظة + الطابع الزمني | النظام |

**ضمانات السلامة:** تجزئة SHA-256 عند كل مرحلة، تحقق إعادة حسابي في أي وقت (زر «التحقق من السلامة»)، وعدم التلاعب يُكتشف تلقائياً ويُسجل.

## 4. حماية بيانات الضحية

| المبدأ | التطبيق |
|---|---|
| **الموافقة المستنيرة** | شاشة أذونات تفصيلية + إشعار خصوصية قبل أي تفعيل + إمكانية الإيقاف في أي لحظة |
| **تقليل البيانات** | لا يُرفع إلا البلاغ المؤكد؛ الرسائل المحلية تُحذف بعد 30 يوماً |
| **التشفير الشامل** | AES-256 + HMAC لكل محتوى محفوظ على الجهاز؛ المفتاح في Keystore ولا يغادر الجهاز |
| **إخفاء الهوية** | أرقام المرسلين تُجزَّأ (SHA-256) قبل المزامنة؛ لوحة التحكم لا تعرض هوية الضحية إلا للصلاحية المخولة |
| **حق الوصول والتصدير** | `GET /me/export` — الضحية تصدر كل بياناتها متى شاءت |
| **حق الحذف** | حذف البلاغات والأدلة المحلية من الإعدادات + إيقاف الحساب |
| **إخبار الجهات** | الأدلة تُشارك حصراً مع الجهة المختصة عبر البلاغ الرسمي — لا مشاركة عامة أبداً |

## 5. الأدوار والمسؤوليات (RBAC)

| الدور | الصلاحيات | محظور عليه |
|---|---|---|
| **ضحية (victim)** | تلقي الحماية، الإبلاغ، تقييم الكشف، متابعة قضيتها، الحظر الشخصي، تصدير بياناتها | كل الوحدات التشغيلية (→ 403) |
| **محقق (investigator)** | عرض البلاغات، القضايا الجنائية، توثيق المراحل، الأدلة | إدارة المستخدمين، سجل التدقيق الكامل |
| **مشرف (supervisor)** | كل ما سبق + تحديث حالات القضايا + إشعارات الضحايا | إدارة المستخدمين |
| **مدير (admin)** | كل شيء + إدارة المستخدمين والأدوار + سجل التدقيق | — (كل إجراء يبقى موثقاً باسمه) |

## 6. سير القضية القانوني (Workflow)

```
بلاغ موثق (EXT-...)
   │
   ├─► مراجعة أولية (under_review) — فرز وتحقق من الأدلة
   │
   ├─► تحقيق (investigating)
   │       ├─ تحليل الأنماط: هل المرسل «محترف»؟ (ضحايا متعددون)
   │       ├─ مذكرة تفتيش (warrant) → ضبط الجهاز → تصوير جنائي
   │       └─ استخراج الملفات (File Carving / SQLite Analysis)
   │
   ├─► الإجراءات الترميمية (remediation)
   │       ├─ أمر إزالة سحابي (takedown) → مزودو المحتوى
   │       └─ حذف آمن للمحتوى المسترد (بعد إتمام التحقيق)
   │
   └─► الإغلاق (closed/rejected) — مع إشعار الضحية في كل انتقال
```

## 7. أوامر الإزالة السحابية (Cloud Takedown)

- **الآلية:** النظام يولّد الطلب ويوثق المزود وعدد الملفات ويتابع الحالة
  (`submitted → acknowledged → actioned/rejected`) مع إعادة المحاولة.
- **القنوات الحالية:** تتبع يدوي بواجهة موحدة (المزودون يقدمون قنوات قانونية رسمية:
  نماذج Legal Removal، أوامر المحاكم).
- **التوسع:** تكامل API مباشر مع بوابات المزودين القانونية — البنية جاهزة (حقل provider + حالات).

## 8. الحدود والإخلاء المسؤول

1. **ليست استشارة قانونية** — الوثيقة إطار تشغيلي؛ الصياغة النهائية للأوامر تتم عبر النيابة/القضاء.
2. **لا إجراء تقني ذاتي** — كل تنفيذ ميداني خارج نطاق البرمجية وبأمر رسمي.
3. **دقة الكشف بشرية** — محرك الكشف قابل للخطأ؛ لذلك وُجدت **تغذية راجعة إلزامية** من الضحية
   (تأكيد/سوء فهم/غير متأكد) ومؤشر `confirmed_precision` يُراجع دورياً.
4. **المنصة أداة مساعدة للجهات** — لا تحل محل قرار النيابة أو القاضي.
5. **التكييف المحلي** — الأعمار، صلاحيات الضبط، مدد الاحتفاظ، وصيغ الأوامر تُطابق التشريع النافذ
   في الولاية القضائية قبل التشغيل.

## 9. لماذا هذا التصميم يصمد أمام اللجنة

- كل تقنية مستخدمة **معروفة ومعتمدة عالمياً** (Forensics، Legal Workflow، Takedown Tracking).
- الابتكار في **الدمج والتكامل بالعربية** — لا في اختراع تقنيات.
- كل إجراء **موثق وقابل للتدقيق** — وهو جوهر الأدلة الجنائية.
- الضحية **محورية**: حماية، متابعة، دعم نفسي، وحقوق بيانات كاملة.
